# 章鱼 AI · 上水日报

> 每日上水，新鲜活泼。

一套自动采集公开市场与资讯数据、生成中文日报、检查新鲜度并推送到微信的 Python 流水线。推送默认使用 **pixel 主题（DOS 复古监视器 / Retro Pixel Market Quest v3）**，也可切换 `forum` 暗色社区仪表盘、`dossier` 德国档案风或 `guizang` 归藏简洁；概率与策略以规则、量化合成为主，港股七日分析可选接入大模型。所有结果仅供参考，**不构成投资建议**。

## 快速开始

需要 Python 3.11+ 和 `requests`。只想生成本地日报时无需推送令牌；要推送到微信，先在本地环境设置 `PUSHPLUS_TOKEN`，或在 GitHub Actions 中配置同名 Secret。

```bash
cd /path/to/02
python3 -m pip install requests
python3 output/pipeline.py --no-push   # 先生成、不推送
python3 output/push.py                # 完整流程：采集 → 分析 → 生成 → 新鲜度检查 → 推送
```

| 产物 | 位置 | 用途 |
|---|---|---|
| 最新日报 | `output/latest.html` | 本地查看或推送使用 |
| 日期归档 | `output/daily_report_YYYYMMDD.html` | 按日期保存的完整日报 |
| 量化预测记录 | `output/quant_history.json`、`output/weekly_forecast.json`、`output/hk7_forecast.json` | 记录预测，并在目标交易日后按真实收盘结算 |
| 新闻与情绪记录 | `output/news_history.json`、`output/sentiment_history.json` | 支持跨日去重、政策窗口与情绪基线 |

## 内容口径与阅读提示

| 页面标记 / 数字 | 含义 | 阅读时注意 |
|---|---|---|
| **当天** | 来源内容日期与报告日一致 | 仍需结合栏目本身的统计窗口理解 |
| **非当天 / 滞后** | 内容日期早于报告日，页面会标出日期 | 滞后报价不计入核心指数均值，不应当作实时价格 |
| **今日抓取** | 今天采集到的前瞻日历快照，不代表事件今天已发生 | 不参与“当天内容”推送门禁 |
| **暂缺 / 未展示** | 来源或对应数据块没有可用内容 | 总结的“数据覆盖”会列出暂缺来源；不会用旧数据补位 |
| **概率与回测** | 根据历史数据或明确规则得到的统计结果 | 概率不是保证；样本不足时只报样本量，不下命中率结论 |
| **AI 研判 / AI帮你提鲜** | 基于本次页面数据规则合成的辅助说明 | 是阅读辅助，不是独立数据源，也不是投资建议 |
| **↳ 同子栏合并** | 同一批数据只在第一个（或口径更专业的）栏目展开，后出现的栏目保留子栏标题 + 一行指针 | 数字不会少：按指针去对应栏目核对；结论三栏（总结 / 今日预判 / 短线速查卡）仍会复述关键数字 |

行情会带对应市场的 `as_of` 日期。若 Yahoo 行情落后，系统会用较新的独立行情基准核对；不能确认日期更新时不覆盖原值。标题情绪只依据资讯标题，不会从价格涨跌反推新闻观点。社区热度与观点未经核实，不等同于事实。

#### 【六眼飞鱼】量化 MACD 策略 · MACD 量化策略

默认开启，放在「【六眼飞鱼】量化 MACD 策略」内部，不另起栏目。默认观察 **9 只指数**：恒指、恒科、国企指数，上证、深成、创业板，以及道指、标普 500、纳指。逐只列出实际收盘日、DIF / DEA、MACD 柱、金叉 / 死叉或延续状态、零轴位置、柱体动能、规则动作，并披露日线根数、供数来源和最近交叉日。只用 MACD 数据也能展示本子块，但不会凭空生成跨市场信号分。

- **计算口径**：`DIF = EMA12 − EMA26`；`DEA = EMA9(DIF)`；页面使用国内双倍柱 `MACD = 2 × (DIF − DEA)`。EMA 以首窗口均值播种，至少 **36 根有效已收盘日线**，才能比较两个已预热时点。原有 `stats.macd` 的单倍差值口径保留，避免改变五因子引擎。
- **只做多 / 空仓的规则**：最新日线金叉且 DIF、DEA 都在零轴上方 → 下一交易日观察入场；多头排列且双线在零轴上方 → 持有；死叉或空头排列 → 退出 / 规避；零轴下方金叉只观察反弹。延续状态不会每天冒充一次新金叉。它不是上涨概率，也不宣称回测胜率。
- **数据优先级**：只读 `market_db.load_daily_bars()` → 复用本次港股量化结果的 `bars` → 仅对缺项并发补取免费接口。同日期先选派生所需历史 / 高低价完整的序列，避免短库或纯收盘库遮盖已有长 OHLC 日线；否则保留基础 MACD，并尝试 2 年整段补足，失败不抹掉基础信号。免费源为 Yahoo `query1` → `query2` → 东方财富 `push2his` 日 K（含 `91` / `63` 镜像）；`^IXIC` 的旧 `100.NDX` 映射未经核验，禁用该免费备用路由而不串用另一只指数。无需行情密钥；短序列、旧日期或解析无效也会触发回退。已有更近真实收盘时不因「库优先」回退日期；整段选源，不混接不同供应商 / 复权口径。
- **市场库不是现成历史 K 线库**：每天三档快照不能当成三根日 K。按 `eod_close` / `eod_close_tdx` 的真实行情日去重；指数可补用有收盘后报价时间、至少双源一致的共识价。必须在原采集时刻就已收盘，今天重新读取也不会把过去存下的盘中半日线变成最终收盘。个股价格口径分组，已知除权窗口交给免费源重取；缺日不补造数据。
- **完成性与新鲜度**：A 股 15:10、港股 16:15、美股纽约当地 16:15 之后才接受当天日线（含保守缓冲，美股自动处理夏令时；提前收市日保守等待常规收盘）。不推算假日，不合成缺日。按报告的北京时间日期检查，滞后超过 **4 个自然日**的序列不发信号；长假也不会放宽后冒充实时。读取库 / 今天计算过不等于「当天行情」，不使用快照标记绕过推送门禁。
- **缺失与版面**：单只失败只影响该行，部分可用时披露缺项原因；连续动能、形态、布林与周日分支各自检查样本 / 高低价 / 周定稿，缺项不补中性、异常不拖垮基础 MACD；全部失败则不显示空 MACD 区块，在总结的数据覆盖里点名。两套主题在 `--notes` / `--full` 下都保留公式和风险口径（默认入门版只出信号表、最近交叉、派生命中与暂缺）；精简版最多 9 行，超出的有效标的说明收起数量，`--full` 恢复全部。

#### 【滚滚翻车鱼】板块轮动量化策略

这是一份**研究性观察篮子**，不是官方 A/H 板块映射，也不构成投资建议。概念池来自东方财富 `push2` 概念列表（`fs=m:90+t:3`，最多翻 5 页）；代码只按仓库内人工维护的白名单关键词，把命中的 A 股概念名称对应到若干港股公司观察篮子。未命中项保持未映射，不用名称相似度猜关系。概念库是当下快照，没有点时成分历史，因此当前实现不宣称历史回测或样本外有效性。

#### 【巡游旗鱼】申万一级行业轮动

这是 **A 股自身** 的行业轮动栏目（与【滚滚翻车鱼】的「A 股概念 → 港股观察篮子」是两件事），2026-10-04 由 PR #84 的股票池修正移植回线上。**纯规则研究口径，不含交易成本，不构成投资建议。**

股票池固定为**申万一级 31 个行业**（申万 801xxx ↔ 东方财富板块指数 BKxxxx 对照表，2026-09-29 逐个按 kline 返回的板块名核对）。历史上该栏目曾整栏缺席 58 次，根因是运行时向东方财富 `clist/get?fs=m:90+t:2` 拉「完整行业列表」——大页请求在境外出口一律被 **502** 拒绝（同分钟 `pz=5` 小页与板块日 K 都是 200），且东财已把行业板块改成申万式三级混排（496 个父子板块并列、无层级字段），不再适合做轮动池。现在主流程**零 clist 调用**。

| 环节 | 口径 |
|---|---|
| 日线 | 板块指数日 K（`klt=101`，180 根），前复权 / 不复权两种口径先用样本行业探测能返回数据的那个，再按该口径取全部行业；当天盘中不含未收盘 K 线（北京时间 15:30 后视为完整）。 |
| 兜底 | 单个行业在东财三台主机都取不到时，逐行业走申万宏源研究所官方指数发布接口；官方源通常滞后一个交易日，滞后行业按「锚点不一致」自动不评分，**同一行业绝不混源**。 |
| 锚点日 | 各行业最后收盘日的众数，必须落在最近完整收盘日；距今超过 14 个自然日 → 整栏缺席（不用过期锚点冒充当日信号）。 |
| 评分 | 近 5 日收益作当周信号；历史 12 个不重叠已结算 5 日窗口算胜率与赔率；零赢或零亏的行业不评分。综合分 = 胜率×80% + [赔率/(1+赔率)]×20%（×100）。20 日 / 60 日收益与 vs MA20 只作背景因子，**不参与排序**。 |
| 月度持仓 | 每月首次成功运行按收盘信号确定前五与目标权重（各自得分 / 前五总分），**下一交易日收盘执行**；当月不随每日评分换仓。 |
| 反馈闭环 | 从执行日收盘起算逐只、组合加权与全行业等权基准表现，超额以 pp 展示；样本只有一个年度周期的一部分，不代表长期有效性。 |
| 判死门槛 | 需 ≥66 根日线才评分；可评分行业少于 max(5, 60%×股票池) = **19** → 整栏缺席（覆盖不足时的「前五」没有意义）。 |

每次运行（成功或失败）都把诊断写入 `output/news_history.json` 的 `industry_rotation_diag`（跑没跑、复权口径、锚点、覆盖、判死原因），随日报一起提交，便于隔日核查「栏目为什么缺席」；月度持仓存档在 `industry_rotation`，与港股板块轮动的 `sector_rotation*` **互不覆盖**。运行日志在成功时点名锚点 / 有效行业数 / 供数来源 / 未取到 / 名称漂移，失败时点名判死原因。

## 新鲜度与推送规则

| 场景 | 处理方式 |
|---|---|
| 数据来源回退 | 每条注册的数据线有 1 个主源和 2 个备用源；主源无响应或正文无效时依次回退。实际使用的备用源会记入日志和总结。 |
| 当天内容检查 | 至少一个数据源抓到当天内容，日报才通过默认推送门禁。前瞻日历属于“今日抓取”快照，不能单独打开门禁。 |
| 当天检查未通过 | 默认不推送日报，但会发送纯文本检查告警；需要研究用状态报告时可用 `--allow-incomplete-push`。 |
| 无数据的栏目 | 不显示空栏目，也不拿历史数据冒充实时值；暂缺来源在“数据覆盖”中说明。 |
| 推送可恢复错误 | 网络异常、HTTP 429/5xx 或发送频繁等错误按 10 秒、30 秒、60 秒退避重试，最多 4 次；不可恢复错误立即失败。 |
| 推送仍失败 | 日报发送失败会尝试发送纯文本告警；推送或告警失败以退出码 1 结束，便于 Actions 标红。 |
| 微信推送标题 | 固定为 `[OCTOPUS] 章鱼 AI · 上水日报 - MM/DD HH:MM`（北京时间）；强制推送为 `[OCTOPUS] 章鱼 AI · 上水日报(强制) - …`，状态报告为 `…(状态) - …`，超长分条在末尾追加 ` (i/N)`。2026-10-13 起前缀由 `🐙` 改为 `[OCTOPUS]` 关键词（emoji 在部分微信客户端与转发链路会被裁掉，关键词也能直接用作消息过滤规则）；页面刊头与 `<title>` 仍是不带前缀的「章鱼 AI · 上水日报」，「日报未推送提醒」「日报推送失败提醒」两条告警仍带 🐙。四条推送路径统一走 `build_push_title()`。 |
| 单条内容超限 | 默认上限按 PushPlus 会员 100,000 字符配置；低于上限一页发送，超限则按原 HTML 在栏目 / 完整标签边界拆分，续片重新带栏目头，**不再自动切换成失去 pixel / forum / dossier 等主题的白底纯文字版**。默认最多 12 条、条间 2 秒，并按平台频率限制排队。 |

**账号额度请按实际情况设置**：PushPlus 文档列出的会员额度为 10 万字、实名用户为 2 万字。可用 `PUSHPLUS_MAX_CONTENT_CHARS` 覆盖默认值。设置 `PUSHPLUS_MULTIPART=0` 会关闭完整分条，改为安全截断并附完整版链接；磁盘归档仍保留完整报告。

```cron
# 每天北京时间 09:00 至 21:00 每两小时运行一次（09:00/21:00 推送微信，其余时段静默更新数据）
0 9-21/2 * * * cd /path/to/02 && ./output/auto_push.sh >> /tmp/octopus.log 2>&1
```

GitHub 定时任务可能受平台负载影响而延迟；若发送失败，工作流会失败退出，不会静默显示成功。

三个工作流的提交推送统一走 `tools/safe_push.sh`：作业从「检出那一刻的 main」出发跑几分钟，
期间 main 可能被 PR 合并 / 另一个工作流推动，裸 `git push` 会被拒（`! [rejected] … (fetch first)`）
并让这一轮的日报与预测留痕全部丢在 runner 上。被拒后脚本会把本次改动**重放**到远端最新提交之上再推
（最多 5 次，退避 + 抖动）：日报 HTML 以本次为准，5 个留痕 JSON 按
`tools/merge_generated.py` 的规则做并集（已结算留痕与官方溯源不被降级、两边条目都不丢），
市场数据库文件因自带 sha256 自校验而整份取本次，**别人的代码与文档一律保留远端版本**。
不是「远端前进」类的失败（权限 / 保护分支 / 钩子拒绝）会立即失败并打印 git 原始输出，不做无谓重试；
万一 5 次都推不上去，这一轮的生成物会作为 Artifact 保留 14 天，可人工补提交。
回归见 `tests/test_safe_push.py`，事故复盘见 `自动更新推送被拒-原因诊断.md`。

本地查看实际报告或排版示例：

```bash
python3 output/preview_server.py
```

打开 `/` 或 `/sample` 查看当前 `output/latest.html`；旧 guizang 示例在 `/legacy-sample`。历史归档不会自动换主题，查看最新风格请认准 `latest.html` 的 `octopus-theme` 元标记。微信超长日报会保持该主题分条发送，而不是变成另一套版式。代码更新不会改写已经送达微信的消息；下次推送才会使用新逻辑。`--push-only` 仅转发已有 HTML，即使指定 `--theme` 也不会给旧日报换肤；需重新生成后再推送。

### 量化引擎分层

| 模块 | 职责 |
|---|---|
| `providers` | Yahoo / 东方财富日与周 K、成交、资金流等数据；可校验候选序列并返回实际主备源 |
| `macd_strategy` | 市场库 / 已有日线 / 免费源编排、历史补足、MACD 交叉与严格零轴过滤、双主题子块呈现 |

| `features` | MOM、TRD、REV、VOL、FLOW 五因子与趋势特征 |
| `probability` | 历史滚动重算、分桶、保序回归（PAVA）、逻辑回归校准 |
| `liquidity` | 南北向成交、量能、Amihud 非流动性、CR5 / CR20 集中度及综合分 |
| `engine` | 编排计算、推进式回测、预测留痕与后续结算 |
| `render` | 结果渲染为 HTML，由流水线注入主题排版 |

引擎内部的计算顺序与模块分层相互配合：

| 阶段 | 处理 | 结果 |
|---|---|---|
| ① collect | 收集指数 / 个股日线、沪深港通成交与港股成交数据 | 标准化数据序列 |
| ② features | 逐日计算五因子；每个时点只使用当时可得数据 | 因子分数与特征 |
| ③ probability | 用历史样本校准概率，并进行滚动检验 | 概率、区间与回测指标 |
| ④ liquidity | 计算成交量、资金流与市场深度 | 流动性画像及有界概率修正 |
| ⑤ validate | 推进式回测；预测写入记录并于之后结算 | 命中率、Brier 与预测复盘 |
| ⑥ decide | 综合概率、区间和趋势状态 | 一句话预测概括 |

## 隐藏功能：市场数据库（AI 基础数据）

2026-10-01 新增的**隐藏功能**：不进日报正文、不进微信推送、不出现在 `--help` 里，
与日报的当天检验 / 推送门禁完全解耦，只在后台按点积累数据。

每天三次（北京时间 **08:00 / 12:30 / 17:00**）抓取股票行情快照，落库到
`output/market_db/YYYYMMDD.json` —— **文件以日期为名字**，当天三档写进同一个文件
（`0800` / `1230` / `1700`，同档重拉覆盖并留痕）。这份库是 AI 分析、AI 预测、
AI 模型的基础数据：每只标的都带多源明细、共识价、置信度、价差与滞后标记，
以及可直接训练 / 分析的特征与标签（见下文「AI 数据集」）。

### 三条硬规则

| 规则 | 落地方式 |
|---|---|
| 源头 >3 | 6 路独立源：东方财富 `push2`、新浪 `hq.sinajs`、腾讯 `qt.gtimg`、Yahoo `chart`、东方财富 `push2his` 日K（收盘校验源）、通达信 `mootdx`（沪深行情 + 日K收盘核对）。HTTP 源每路都带镜像主机，通达信走主站池逐个降级（TCP 预检 + 先验活后明细 + 总预算 90s，见下文「防卡死」）；单路失败只影响该路，全失败**不落库**（绝不写空文件、绝不补历史数字）。 |
| 交叉验证 | 同一标的跨源比价：中位数 + MAD 稳健离群，逐源判定「滞后」（比最新行情时间落后 >30 分钟），输出共识价 / 离群源 / 价差百分比 / 置信度（高 / 中 / 低 / 单源）；≥2 路一致才计入「有效共识」，冲突（价差 >3%）单独点名。 |
| 自我检查 | 每次落库做一遍体检并写进文件 `self_check`：时段合法性、计划时刻偏差、成功源数（≥4）、标的覆盖率（≥80%）、有效共识率（≥90%）、价格与涨跌幅合理性、跨源冲突、同日跨时段跳变、跨日跳变、当天行情时效、文件哈希。 |

### 常用命令（隐藏入口二选一）


`output/market_db.py` 不依赖第三方库（有 `requests` 用 `requests`，没有就回退标准库 `urllib`），

沪深行情；没装或主站连不上时该源标记 `unavailable`，其余 5 路照常，绝不编数字。

标的池默认为「港股三大指数 + 18 只港股蓝筹 + A 股三大指数与 8 只沪深蓝筹 + 美股三指数与龙头」，
可用 `OCTOPUS_DB_SYMBOLS='0700.HK:腾讯控股,^HSI'` 覆盖；`OCTOPUS_DB_SYMBOLS` 也可在
workflow 的仓库变量里配置（Actions → Variables）。

### AI 数据集

`build_dataset()` / `export_dataset()` 把库拍平成一行一条快照的记录：

- **特征**（只用当次及之前的数据，无未来函数）：`price`、`change_pct`、`prev_close`、
  `open/high/low`、`volume/amount`、`spread_pct`、`n_sources`、`confidence`、`n_lagged`、
  `slot_index`、`ret_prev_slot`、`ret_day_open`、`ret_1d`、`ret_5d`、`vol_5d`；
  以及通达信通道的 `pe`、`pb`、`total_mv`、`float_mv`、`days_since_action`
  （财务按「当时已知」前向填充 —— 早盘不会拿 17:00 才落库的财务去回填）；
- **标签**（只用之后的数据）：`next_slot_ret`、`eod_ret`、`next_day_eod_ret`；
- **质量标记**：`verdict`（一致 / 冲突 / 孤证…）、`lagged`（滞后源）、`consensus`（是否有 ≥2 路共识）。

`ai_context()` 直接给出最近一档的共识价 + 新鲜度（`age_hours` / `stale`）+ 自检得分，
供 AI 分析 / 预测在提示词里引用；库文件里的 `ai` 块是当天数据的即时摘要。
CI 每次运行还会导出 `output/market_db/ai/dataset.jsonl` 并作为 Actions Artifact 上传
（该目录不进版本库，避免仓库膨胀）；库文件本身正常入库，需要瘦身时用 `prune --keep-days`。

### 通达信通道（mootdx，2026-10-01 升级）

`mootdx`（MIT，v0.11.7）是通达信行情协议的 Python 封装，作为第 6 路源接入：

- **行情**：`Quotes.factory(market='std')` 取沪深实时快照（`quotes()`），补进当日共识价；
  港美股不在通达信标准行情覆盖内，该源只对沪深标的生效（代码映射 `600519.SS → sh600519`）。
- **收盘核对**：每档都取日K（`bars(frequency=9)`）最后一条收盘，与东财 `push2his` 日K
  组成**双源收盘核对**（`consensus.eod_close_checks`），互相印证上一交易日收盘价；
  跳变若由除权除息造成，会写明「疑似除权除息」并免于扣分。
- **行情时间**：通达信只回 `HH:MM:SS`，日期用日K最后一根推出的交易日补全 ——
  盘前拉到的其实是上一交易日的收盘快照，不会被记成当天盘中价（不造时间戳）。
- **财务 / 除权除息**：只有 **17:00 收盘档**才抓 `finance()`（总股本 / 净资产 / 净利润
  → 市值、PE、PB）与 `xdxr()`（近 45 天除权除息），写进 `fundamentals` / `corporate_actions`，
  同时进入 AI 数据集与 `ai-context`。
- **降级**：`mootdx` 未安装、主站全连不上、返回空数据时，该源标记 `unavailable` / `failed`，
  其余 5 路照常入库；`OCTOPUS_DB_TDX=0` 或 `pull --no-tdx` 可整体关闭。
- **主站池**：默认用 mootdx 内置主机列表（最多试 4 个，可 `OCTOPUS_DB_TDX_SERVERS=1.2.3.4:7709,…`
  覆盖），连上哪个就把实际 host 写进 `sources.tdx.host`。

#### 防卡死四道闸（2026-10-01 事故后加固）

一次定时运行被**单台死主站**拖到 20 分钟上限被取消：`tdxpy` 的 `connect()` 会把
`socket.timeout` 吞掉并 `return False`，`mootdx` 又不检查返回值 —— SYN 被丢弃的死站被当成
「连上了」，之后每次 API 调用都跑一遍 `auto_retry` 阶梯（4 次重连 × 5s + 退避 sleep）。
11 只沪深标的 ≈ 34 次调用，单站 ~6 分钟、4 站 ~24 分钟 > 20 分钟作业上限；被 kill 时
stdout 缓冲整段丢失，日志里只剩 `mootdx` 那三行 stderr 提示，看着像「配置文件问题」。
四道闸逐条对症（[原因诊断](./通达信通道-作业被取消-原因诊断.md)）：

| 闸 | 做法 | 效果 |
|---|---|---|
| ① 预置配置 | 建客户端前先写好 `$HOME/.mootdx/config.json`（SERVER 主机池 + BESTIP；`OCTOPUS_DB_TDX_CONFIG` 可换路径）；已存在的配置原样尊重 | 不再出现「未找到配置文件 / 请手动运行 `python -m mootdx bestip`」，也不会写出 `BESTIP=""` 的半残配置 |
| ② TCP 预检 | 先用自己的 socket 探一次（`TDX_PROBE_TIMEOUT`=3s），连不上的站**不交给 mootdx** | 死站 3s 换台，不再进入 tdxpy 重连阶梯 |
| ③ 先验活后明细 | 每台主站先做一次 `quotes()`（全标的、一次调用），行情为空立刻换站；客户端显式 `auto_retry=False` | 一台坏站最多花 1 次调用，而不是 34 次 |
| ④ 总预算 | `TDX_BUDGET_SEC`=90s（`OCTOPUS_DB_TDX_BUDGET` 可覆盖）约束整条通道，到点收工并如实写失败原因 | 单路再坏也不会拖垮作业；其余 5 路照常入库 |

> 工作流侧同步加固：`PYTHONUNBUFFERED=1`（被取消时日志不丢）、采集步骤 8 分钟超时兜底。

> 说明：新浪与腾讯的美股字段口径与 A / 港股不同，未纳入比价（避免误读数字）；
> Yahoo 对港股 / A 股可能延迟 15 分钟，滞后源会被标注并从共识价中剔除，但保留在
> `by_source` 明细里。库文件里的哈希用于发现手工改写；`verify` 会点名被改写的日期与档位。
